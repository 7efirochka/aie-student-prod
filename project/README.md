## 1. Паспорт проекта

- **Название проекта:** `MovieRecommender - сервис рекомендаций фильмов на основе жанров и описания`
- **Автор:** `Рубцова Галина Игоревна`
- **Группа:** `ИКБО-11-24`
- **Контакт:** `s7ombra@gmail.com`

- **Краткое описание (2-4 предложения):**  
  `Проект представляет собой REST API-сервис для рекомендаций фильмов на основе контентного подхода. Система использует гибридную модель, объединяющую информацию о жанрах (через MultiLabelBinarizer) и текстовые описания фильмов (через TF-IDF векторизацию). Для поиска похожих картин вычисляется косинусное сходство между векторами признаков. Сервис позволяет пользователю ввести названия нескольких любимых фильмов и получить список наиболее релевантных рекомендаций с учетом года выпуска и рейтинга.`


## 2. Структура проекта

Проект организован в следующей структуре:

- `requirements.txt` – зависимости проекта (fastapi, uvicorn, pandas, numpy, scikit-learn, python-dotenv).
- `report.md` – отчёт по проекту (постановка задачи, данные, эксперименты, результаты).
- `self-checklist.md` – чеклист самопроверки проекта перед сдачей.
- `notebooks/` – экспериментальные ноутбуки:
  - EDA, прототипы моделей, отдельные эксперименты.
- `src/` – основной код проекта:
  - `src/data/create_dataset.py` – скрипт для сбора данных через TMDB API и сохранения в CSV.
  - `src/models/train.py` – модуль обучения модели: генерация признаков, расчет матрицы сходства, сохранение артефактов.
  - `src/models/compare_models.py` - бейзлайны и система тестирования всех подходов рекомендаций. 
  - `src/service/recommender.py` – класс `MovieRecommender`, реализующий логику загрузки модели и поиска рекомендаций.
  - `src/service/api.py` - функционал api.
- `data/` –  папка для хранения датасета `movies_1990_2026.csv`, созданного с помощью TMDB API.
- `configs/` – конфигурационные файлы:
  - `.env` – файл с API-ключом TMDB (игнорируется в Git).
  - `.env.example` - файл с API-ключом TMDB для ввода пользователем, чтобы использовать TMDB API.
- `tests/` – тесты (юнит-тесты, простые проверки).
  - `tests/test_api.py` - pytest для тестирования основной системы.
- `artifacts/` – сохранённые модели, отчёты, результаты экспериментов:
  - `cosine_hybrid_matrix.npy` – предвычисленная матрица косинусного сходства для гибридного подхода.
  - `encoders.joblib` – объекты векторизаторов и маппинг ID фильмов.
  - `cosine_description_matrix.npy` - предвычисленная матрица косинусного сходства для описаний фильмов.
  - `compare_models.json` - файл сравнения бейзлайнов и основной модели по тестам.
  - `genres_distribution.png` - распределение жанров в датасете.
- `.gitignore` – настройки исключения файлов из репозитория.

## 4. Как запустить проект

### 4.1. Подготовка данных (Опционально)

В файле  `data/movies_1990_2026.csv` уже содержиться датасет с более чем 11-ю тысячей фильмов.
Задать собственные параметры для сбора данных можно в файле `src/data/create_dataset.py`

Для работы скрипта сбора данных необходимо создать файл `.env` в корне проета и добавить туда ваш API ключ от сайта TMDB:

```bash
TMDB_API_KEY='your_api_key_here'
```
Пример заполнения файла `.env` лежит в файле `configs/.env.examples`

Запуск программы сбора данных (убедитесь, что вы находитесь в директории `project`):

```bash
uv run python -m src.data.create_dataset
```

### 4.2. Запуск обучения модели

Перед запуском API необходимо обучить модель и сохранить артефакты в папку artifacts/:

```bash
uv run python -m src.models.train
```
После выполнения в папке artifacts/ появятся файлы `cosine_hybrid_matrix.npy` и `encoders.joblib`.

### 4.3. Запуск сервиса (FastAPI/Docker)

Способ 1: Локальный запуск через Uvicorn

```bash
uv run uvicorn src.service.api:app --reload --host 0.0.0.0 --port 8000
```

Сервис будет доступен по адресу: `http://localhost:8000`
Документация Swagger UI: `http://localhost:8000/docs`  

Способ 2: Запуск с помощью Docker:

```bash
cd project
docker build -t movie-recommender .
docker run -d -p 8000:8000 -v ${PWD}/data:/app/data -v ${PWD}/artifacts:/app/artifacts --name movie-api movie-recommender
```

Остановка контейнера:
```bash
docker stop movie-api
```

Сервис поднимается на порту 8000 и доступен по адресу `http://localhost:8000`. При первом запуске сервиса наблюдается задержка ~20 секунд.
  - `GET /health` - проверка состояния приложения и статуса загрузки модели.
  - `POST /recommend` - основной эндпоинт для генерации рекомендаций. Принимает JSON-объект с названиями фильмов и параметрами фильтрации, возвращает ранжированный список похожих фильмов.

### 4.4. Запуск бейзлайнов и тестов

С бейзлайнами и тестами можно ознакомиться в папке `project/src/models/compare_models.py`

Запуск тестов для бейзлайнов и итоговой модели:

```bash
uv run python -m src.models.compare_models
```

Результаты тестов будут в папке: `artifacts/compare_models.json`

## 6. Тесты

В проекте реализованы базовые тесты для проверки работоспособности системы:

- Sanity-чеки - `test_root_endpoint` — проверка корневого эндпоинта /.
- Интеграционные тесты - `test_recommend_valid_input`, `test_minimum_output_n`, `test_case_insensitive` - проверка работы API-эндпоинтов.
- Тесты бизнес-логики - `test_exclude_match`, `test_rating_sort` - проверка специфичных правил рекомендательной системы.
- Тесты обработки ошибок - `test_invalid_input`, `test_empty_input` - проверка корректной реакции на невалидные входные данные.
- Тесты данных - `test_normal_genres` - проверка формата и содержания возвращаемых данных.

Для запуска всех тестов выполните из корня проекта:

```bash
uv run pytest tests/test_api.py
```

## 8. Ограничения и дальнейшая работа

Текущие ограничения:

- Модель работает в режиме offline-батча: матрица сходства пересчитывается только при переобучении. Добавление новых фильмов требует полного перезапуска пайплайна.
- Поиск по названию чувствителен к опечаткам (используется точное совпадение строк).
- Нет учета пользовательских предпочтений (истории просмотров), только контентная фильтрация.

Направления развития:

- Интеграция векторной базы данных (Qdrant/FAISS) для динамического добавления новых фильмов без пересчета всей матрицы.
- Внедрение алгоритма для устойчивости к опечаткам в названиях.
- Добавление персонализации на основе истории оценок пользователя.
