## 1. Паспорт проекта

- **Название проекта:** `MovieRecommender - сервис рекомендаций фильмов на основе жанров и описания`
- **Автор:** `Рубцова Галина Игоревна`

  Проект представляет собой REST API-сервис для рекомендаций фильмов, построенный на гибридном контентном подходе. Модель объединяет жанровые метки (`MultiLabelBinarizer`) и семантику описаний (`TF-IDF`), вычисляя релевантность через косинусное сходство векторов. Пользователь вводит названия понравившихся фильмов, а система возвращает топ похожих картин с поддержкой фильтрации по году выпуска и рейтингу. Решение оптимизировано для быстрого инференса и готово к развёртыванию через Docker.

## 2. Постановка задачи и контекст

Опишите:

1. **Предметную область и задачу:**

      - семейные зрители: пользователи, ищущие фильм для совместного просмотра (без взрослого контента), с учётом предпочтений всех членов семьи.

2. **Формулировку задачи в терминах ML/ИИ:**
   - Входные данные. Формат запроса (JSON, POST /recommend):
      - названия фильмов, разделённые запятой;
      - количество фильмов в подборке;
      - фильтр года выпуска (возвращает фильмы, которые вышли позднее указанного года);
      - фильтр взрослых жанров (если `adult = False`, то исключает фильмы с жанрами для взрослых).
   - Выход модели (JSON):
      Ранжированный список фильмов, отсортированный по убыванию оценки сходства. 
      Поля:
      - `title` - название рекомендованного фильма;
      - `year` - год выпуска фильма;
      - `rating` - средняя пользовательская оценка фильма;
      - `genres` - жанры рекомендованного фильма;
      - `adult` - имеет ли фильм жанры для взрослых;
      - `similarity_score` - оценка сходства с запрошенными фильмами.
   - Ограничения и требования к системе:
      - ОПЦИОНАЛЬНО. Загрузка датасета в память ~3-5 минут;

      - память под матрицу сходства ~400-600 Мб.

      - удаление из итоговой выборки запрошенных фильмов;
      - фильтр по году;
      - фильтр взрослого контента;
      - устойчивость к регистрам и пробелам.
   - Интерпретируемость:
      - в поле `similarity_score` видно, почему фильм рекомендован;
      - веса жанров и описания (0.3/0.7) видны в коде и могут быть изменены;
      - добавлено логирование основных этапов.

   - В данном проекте используется набор детерминированных бизнес-тестов, проверяющих:

## 3. Данные

Опишите, какие данные использует проект:

1. **Источник данных:**
   - The Movie Database (TMDB) API (`https://api.themoviedb.org/3`).

2. **Структура данных:**
   - датасет храниться локально в директории `data/movies_1990_2026.csv`.
   - объём данных ~11000 записей.
   - ключевые признаки (колонки);
      - `id` - int - id фильма на сайте tmdb;
      - `title`- string - название фильма;
      - `year`- int - год выпуска фильма;
      - `description` - string - описание фильма;
      - `genres` - string - жанры фильма;
      - `rating` - float - средняя пользовательская оценка фильма;
      - `num votes` - int - количество пользователей, оценивших фильм;
      - `adult` - bool - есть ли в фильме жанры для взрослых.

3. **Предобработка и EDA:**
   Так как данные собирались через TMDB API, этапы очистки и трансформации были интегрированы в пайплайн сбора `src/data/create_dataset.py`
   1. Загрузка данных осуществлялась постранично с сортировкой по популярности `popularity.desc`, это позволяет отсеять фильмы без пользовательских оценок или малопопулярные фильмы.
   2. Предобработка данных:
      - из строки `release_date` извлекались только 4 первых символа, то есть только год.
      - числовые ID жанров из TMDB API менялись на обычные названия жанров с использованием справочника `genre_map_api`.
      - реализована генерация бинарного признака `adult` (по умолчанию у всех фильмов `adult = False`). Если в жанрах к фильму присутствовали Crime, Horror, Thriller или War, то присваивалось `adult = True`.
   3. Нормализация:
      - были оставлены только колонки, релевантные для контентной рекомендации: `id`, `title`, `year`, `description`, `genres_ids`, `rating`, `num_votes`, `adult`.
      - имена колонак были стандартизированы: 
      `overview` -> `description`;
      `vote_average` -> `rating`;
      `release_date` -> `year`.
   4. Были удалены записи с отсутствующими ключевыми полями через `dropna()`. Также были удалены дубликаты фильмов через: `drop_duplicates(keep='first')`
   5. Подготовка к использованию.
      - текст был приведён к нижнему регистру, лишние пробелы были удалены. Была проведена векторизация через `TfidfVectorizer`.
      - жанры были преобразованы в бинарную матрицу через `MultiLabelBinarizer`.

   Наблюдения из разведочного анализа данных:
   1. В ~3-4% данных описание к фильму не заполнено;
   2. Жанры `Drama`, `Comedy` и `Action` встречаются в 3–4 раза чаще, чем `Western` или `Documentary`.

Основные шаги предобработки лежат в `src/data/create_dataset` и `notebooks/data_process.ipynb`

## 4. Модели и подходы

Опишите, какие модели вы пробовали и как развивался ваш подход:

1. **Базовые (baseline) модели:**
   В качестве baseline были реализованы три простых подхода, не требующих обучения (модели представлены в файле `src/models/compare_models.py`).
   1. Random (`random_films`) - cлучайная выборка n фильмов из датасета. 
   Результаты: Не учитывает жанры, рейтинг или сюжет. Подходит только как sanity-check.
   2. Popular (`recommend_popular`) - возврат топ n фильмов после сортировки всего датасета по рейтингу.
   Результаты: Даёт высокий средний рейтинг, но полностью игнорирует контекст запроса.
   3. Description recommends (`recommend_description`) - TF-IDF + Cosine Similarity только по полю `description`.
   Результат: Хорошо улавливает смысловую близость сюжетов, но может рекомендовать фильмы не того жанра. 

2. **Улучшенные модели и эксперименты:**
   Итоговая система представляет собой гибридную контентную модель (`MovieRecommender`), объединяющую признаки жанров и текстовых описаний в единую матрицу сходства (модель представлена в файле `src/service/recommender.py`).
   Архитектура:
   - Текстовый вектор: `TfidfVectorizer(stop_words="english", max_features=5000, ngram_range=(1,2))`
   - Жанровый вектор: `MultiLabelBinarizer`. Преобразует списки жанров в бинарную матрицу, где каждый жанр - независимый признак.
   - Гибридное сходство:
      hybrid_score = a · cosine_similarity(genres) + b · cosine_similarity(description), где по умолчанию a=0.3, b=0.7.
   Ключевые эксперементы:
      - Поиск весов a/b.
         - при 0.5/0.5 модель теряла сюжетные аналогии, больше внимания уделялось жанрам.
         - компромисс 0.3/0.7 дал максимальную стабильность по тестам.

3. **Нейросетевые модели (если применимо):**
   В текущей версии проекта нейросетевые архитектуры не использовались.

1. **Экспериментальный протокол:**
   - разделение датасета на Train / Val / Test - не применялось.
   - было использовано 100% данных, матрица `cosine_hybrid_matrix.npy`.
   - исключение «утечки данных». Запрошенные пользователем фильмы принудительно исключаются из выдачи (avg_sim_scores[idx] = -1)

2. **Сравнение моделей по метрикам:**

   Тест 1. Фильм с жанром боевик. Условие - минимум в 3 из 5 фильмов в жанрах должен быть Action.
   Тест 2. Семейный фильм. Условия - минимум в 3 из 5 фильмах в жанрах должен быть Family & минимум в 4 из 5 фильмах adults = False & жанрах не должно быть жанров Horror, Crime, Thriller (максимум 1 фильм).
   Тест 3. Хоррор фильм. Условия - минимум в 3 фильмах из 5 в жанрах должен быть Horror & минимум в 4 из 5 фильмах adults = True & в жанрах не должно быть Family (максимум 1 фильм).
   Тест 4. Научная фантастика. Условие: минимум в 3 из 5 фильмов должен быть жанр "Science Fiction".
   Тест 5. Высокий рейтинг. Условие: средний рейтинг рекомендаций >= 5.0.

   Таблица оценивания:

| Модель | test_1 | test_2 | test_3 | test_4 | test_5 | Комментарий |
|--------|--------|--------|--------|--------|--------|-------------|
| **Baseline_1 (random)** | ❌ | ❌ | ❌ | ❌ | ✅ | Случайная выборка не учитывает жанры/описание; проходит только тест на рейтинг за счёт общего высокого уровня оценок в датасете |
| **Baseline_2 (most popular)** | ❌ | ❌ | ❌ | ❌ | ✅ | Сортировка по рейтингу гарантирует высокий средний балл, но игнорирует контекст запроса — рекомендует только блокбастеры |

| **MovieRecommender (hybrid)** | ✅ | ✅ | ✅ | ✅ | ✅ | Гибридная модель объединяет жанровые признаки и текстовую семантику, обеспечивая сбалансированное качество во всех сценариях |

3. **Выбор финальной модели:**
   В качестве финального решения выбрана гибридная контентная модель `MovieRecommender`, основанная на линейной комбинации косинусного сходства по жанрам (MultiLabelBinarizer) и текстовым описаниям (TF-IDF).

## 6. Архитектура решения и сервис

Опишите, как из модели получился работающий сервис:

1. **Архитектура пайплайна:**
   Проект реализует трёхэтапный пайплайн. 
   - ЭТАП 1. Сбор и подготовка данных (`src/data/`):
      Файл: create_dataset.py  
      - Запрос к TMDB API;
      - Изменение genre_ids на человекочитаемые жанры;
      - Эвристическая маркировка adult-контента;
      - Очистка: dropna(), drop_duplicates();
      - Сохранение: data/movies_1990_2026.csv.
   - ЭТАП 2. Обучение модели (`src/models/`):
      Файл: train.py
      - Загрузка и парсинг жанров;
      - MultiLabelBinarizer -> genre_matrix;
      - TfidfVectorizer (max_features=5000, ngram_range=(1,2));
      - cosine_similarity для жанров и текста;
      - Гибридная матрица: 0.3·genres + 0.7·desc;
      - Сохранение артефактов:
        - artifacts/cosine_hybrid_matrix.npy
        - artifacts/encoders.joblib
   - ЭТАП 3. Сервис рекомендаций (`src/service/`):
      Файл: recommender.py
      - Класс MovieRecommender;
      - Загрузка датасета + матрицы при инициализации;
      - Метод recommend(): поиск, фильтрация, сортировка, форматирование ответа.
      Файл: api.py (FastAPI)
      - lifespan: загрузка модели при старте;
      - Эндпоинты: /, /health, /recommend;
      - Валидация через Pydantic;
      - Обработка ошибок через HTTPException.


2. **API и endpoints:**
   - `/` - приветственный эндпоинт, проверка работоспособности сервиса. 
   Возвращает: {"message": "Welcome to the movie recommendation API"}
   - `/health` - health-check: статус загрузки модели.
   Возвращает: {"status": "OK", "model_loaded": true/false}
   - `/recommend` - основной эндпоинт: получение рекомендаций.
   Возвращает: {"recommendations": [...]} или {"error": "..."}

3. **Технологический стек:**

## 8. Ограничения и дальнейшая работа

Будьте честны:

Текущие ограничения:

- Модель работает в режиме offline-батча: матрица сходства пересчитывается только при переобучении. Добавление новых фильмов требует полного перезапуска пайплайна.
- Поиск по названию чувствителен к опечаткам (используется точное совпадение строк).
- Нет учета пользовательских предпочтений (истории просмотров), только контентная фильтрация.

Направления развития:

- Интеграция векторной базы данных (Qdrant/FAISS) для динамического добавления новых фильмов без пересчета всей матрицы.
- Внедрение алгоритма для устойчивости к опечаткам в названиях.
- Добавление персонализации на основе истории оценок пользователя.
